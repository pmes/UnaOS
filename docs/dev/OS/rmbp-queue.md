HOW TO READ IT. `firmware->loader` is an ABSOLUTE stamp — `rdtsc` from the last processor reset — so it is firmware POST **plus Peter's hand at the ⌥ picker**, an upper bound and never a firmware timing; its value is that it is the first REPEATABLE number for that phase, so the comparison that answers A12 is TWO flights of the SAME media, not one flight against a feeling. `loader-read` is the ELF read alone and is the term A12 nominates (it grows with the image every arc). `loader-jump` is load + relocation + ACPI/EDID/volume discovery + `exit_boot_services`. `kernel-entry` is raw cycles at the `BPACE entry` stamp, so `kernel-entry − tsc_loader_jump` is the hand-off gap and `kernel-entry / tsc_hz` is the whole pre-kernel phase — cross-check it against the squawk-mark bound (≤ 47.7 s F8 / ≤ 49.8 s F9) and against `BPACE total gui=`, which it must precede. EXPECTED ORDER OF MAGNITUDE: tens of seconds, versus tens-to-hundreds of MILLISECONDS in QEMU; if the bench prints milliseconds the stamps are not the ones the boot took. THE TWO NULL READINGS, both pre-registered: `firmware->loader=absent loader-read=absent loader-jump=absent` means the card carries a `bootloader.efi` built before this field (re-pack the whole ESP — the loader and the kernel are one ABI and old media silently predates it), and `tsc_hz=0(uncalibrated)` with `cy` suffixes means the ACPI PM timer never calibrated. Neither is a fabricated number, and `kernel-entry=` prints in both.

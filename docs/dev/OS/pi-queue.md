Deduping `K8_FEATS` DOES change `kernel8.img`.** The dedup line was written (the choke-point idiom, `local _k8dd=""; for _k8df in ${K8_FEATS//,/ }; do case ",${_k8dd}" in *",${_k8df},"*) ;; *) _k8dd="${_k8dd}${_k8df}," ;; esac; done; K8_FEATS="${_k8dd%,}"`, placed as the last statement before the banner echo) and the banner half worked exactly as the row says: `genet` 2 → 1, `…,piusb,genet,nettest,pirast,desktop_firmware,quarry`. The byte-compare refused it. LAWS §9's Pi desktop line, `sha256sum` of the FLAT image, alternated A/B/A/B on a warm cache in which NOTHING but `unaos-kernel` recompiled between runs: duplicated banner → `0b6f2381fb3bc8e6982a726010822d7e4a0cd2b1cc616574c24ff02fd66e24ff`, deduped → `405feaac4bb7fba5e3600c309e6efd032c56826bc5529eb06125e9ec41c831b1`, duplicated → `0b6f23…` again, deduped → `405fea…` again. **Deterministic, reproduced twice each, and different.** The images are the same 2984480 bytes and the differing bytes are ADDRESS IMMEDIATES in `.text` (e.g. flat offset 0xC04 `08ad43f9` vs `08a943f9`, an LDR whose offset field moved; 0x39F4 `08e11e91` vs `08c11e91`, an ADD immediate) — a static's address shifted, so this is layout, not behaviour, but it is not byte-identity and the gate this row set was byte-identity. **A SECOND VARIATION SOURCE was found in the same measurement and it matters more than the first**: two builds of the IDENTICAL pristine tree and the IDENTICAL duplicated banner gave `9d3103c36763a5e06ee4effb49c77087b817bfaa474c44cffff27bfb5620d30c` (cold target dir, the run that also compiled the deps and the `user_blob.bin` that `arch/aarch64/syscall.rs:3327` `include_bytes!`es into the kernel) and `0b6f23…` (warm), 2638 bytes apart. **So `kernel8.img` is reproducible across a warm-cache recompile and NOT across a cold one, and no "before/after sha256" of this image means anything unless both sides are built on the same cache state.** Every byte-identity claim in this tree that was proved by two `kernel8` builds across a cold boundary is worth re-reading with that in mind.

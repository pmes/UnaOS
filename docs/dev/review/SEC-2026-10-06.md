# SEC-2026-10-06 — SECREVIEW (rmbp-ledger B442), adversarial review of merge17 (4ead840a)

Peter (2026-10-06): "security vulnerabilities". Scope: ring boundary, `unsafe` in this wave's files, R99 (sacred
boot FAT), R94 (who writes the root's system trees), the Wi-Fi firmware path. Read-mostly; every finding names its
fix. Ranked by severity. Line numbers are at 4ead840a.

## F1 — HIGH — the leaked UI surfaces are sliced past their allocation after a live scale rise (PATCHED)
- **Where.** `video/dialog.rs:176-188` `surf()`, `video/notify.rs:218-232` `surf(i)`, `video/bezel.rs:167-179`,
  `video/instgui.rs:77`, `video/login.rs:154`.
- **Rule.** SECURITY.md "user fault never kernel corruption"; LAWS: a SAFETY comment states what the code proves.
- **What it does.** Each module leaks ONE `[u32]` of `size(W)*size(H)` words at first use, then on every call builds
  `from_raw_parts_mut(p, n)` with `n` recomputed at the CURRENT scale. PREFSUI's Resolution dropdown
  (`settings.rs:1635` → `dpi::set_live`) changes the scale at run time, so after a scale rise every paint of the
  alert, the toast/notification stack, the bezel, the installer GUI or the login screen writes past the end of a
  heap block — a kernel heap overwrite, reachable from the glass (choose a smaller "Looks like" mode, show any
  toast, choose native back) and at login (`via=login` applies the stored `system.display.mode`, which any in-session
  ring-3 program may write — F4). The SAFETY comments ("one leaked buffer of `n` words") were false.
- **Fix (this branch).** `metrics::leaked_surf(at, n)`: word 0 of each leaked block holds its capacity; a larger `n`
  leaks a fresh block and publishes it (an old block stays valid for a reader still holding it). The five sites call
  it. Behaviour-neutral at a fixed scale (same buffer, same bytes).

## F2 — MEDIUM — any ring-3 principal (even `anon`) can retag the root's system trees (PATCHED)
- **Where.** `fs/vfs.rs:1672` (`native_write_authz`: "no owner row -> public object, writable"), reached from ring 3
  by `fs/attrsys.rs:143` `do_set` (`SYS_ATTR_SET` and `BUS_VERB_ATTR_SET`, both arches).
- **Rule.** R94 (root is the boot disk; `/system`, `/apps`, `/lib` are the system's), R79 (type and association
  are UnaFS attributes — so they are authority), SECURITY.md SECLOGIN M4 (kernel-owned objects).
- **What it does.** The kernel creates `/system`, `/system/types/<mime>` (`assoc.rs:164-178`), `/apps`, `/lib` as
  `KERNEL_PRINCIPAL`, which stamps NO `owner` row; the native ACL reads that as world-writable. A ring-3 program
  (x86 `attrsurf_principal` answers `anon` with no session) can set `una:opener` on `/system/types/text/plain` and
  change what every user's double-click opens, or retag `/apps/*`. Both spellings reach it (`/volumes/UnaOS/…`
  resolves to the same volume path).
- **Fix (this branch).** `attrsys::system_tree`: a non-kernel `do_set` on `system|apps|lib` of the ROOT volume
  (resolved, so both spellings) answers `-EACCES`. Kernel and shell (`SHELL_PRINCIPAL` = kernel) are unchanged.
- **Still owed (in BOOTFATSEAM's sibling, ROOTACL).** The posture itself: kernel-created system objects should carry
  a `system` owner so create/write/unlink are refused too.

## F3 — MEDIUM — R99's gate is VFS-only; raw `FatFs` writers mutate the sacred boot FAT (ARC: BOOTFATSEAM)
- **Where.** `fs/bootfat.rs:44` `refuse` is called only from `FatBackend::authorize_write` (`vfs.rs:1424`). Writers
  that hold a `FatFs` and never touch the VFS: `fs/users.rs:538-616` (`USERS.DAT` write/rename on the store volume —
  the boot card's FAT), `fs/holocron.rs:736` (`fat::mount()` = the global slot = the boot FAT), `fs/fat.rs:6170`
  (`fatlfn_witness_once`, `witness` is in the metal shape: creates and deletes a scratch tree on the boot FAT every
  boot — also R80), `selfhost/extract.rs:768`. `fat_unlock` (`bootfat.rs:64`) has NO production caller and does not
  ask `users::admin_authority` — any kernel path may open the gate.
- **Rule.** R99 ("sacred … difficult for root"), R80 (nothing tests at boot).
- **Fix (arc).** Fold the sacred check into `FatFs::write_veto` (the one predicate raw writers already ask) for a
  FAT on the bound root's device; move `USERS.DAT` and the holocron store to UnaFS `/system` (kernel-owned leaf, the
  SECLOGIN M4 guard); FAT-LFN SKIPs `reason=r99-sacred`; `fat_unlock` takes `admin_authority` and the installer and
  updater call it. Not a patch: refusing the raw writers today would refuse the password save on the card.

## F4 — MEDIUM — Principia's bus verbs: any in-session program writes any namespace and declares any stanza (ARC: PREFSCAP)
- **Where.** `prefs_core/src/wire.rs:174-196` (`VERB_SET` checks only `in_session`), `:221-225` (`VERB_DECLARE`'s
  name is caller-chosen), kernel `prefs.rs:843-848` (`DECLARED.insert` replaces, unbounded map).
- **Rule.** SECURITY.md "capabilities first"; R79 (a preference is Principia's — the owner decides who writes).
- **What it does.** Any session program may set `vein.endpoint` / `vein.claudecode.bin` / `vein.key_file` (redirect
  the agent's API traffic and its key, or the binary it runs), `system.login.items` (persistence for any installed
  app), `system.display.mode` (F1's trigger at login). PrefDeclare lets program A replace program B's stanza
  (widening B's kinds), and each distinct name adds up to 32 keys to a kernel map with no cap (heap growth from
  ring 3).
- **Fix (arc).** The transport stamps the caller's program name; `SET` admits `app.<own-name>.*` and the `system`
  keys the schema marks user-settable from ring 3; other namespaces only from their owner (vein from vein);
  `DECLARE` binds `name` to the caller and refuses a stanza another program holds; `DECLARED` capped (64 programs).

## F5 — MEDIUM (latent; HIGH once `wifi2` uploads) — Wi-Fi microcode is not pinned and may come from a removable volume (ARC: FWPIN)
- **Where.** `wifi/firmware.rs:132-139` (`FW_SET`: names only), `:469-476` (FNV-1a reported, never compared; a
  `stream=violates-layout` image is still STAGED), `drivers/block.rs:506-527` (`alternate_program_source` returns
  the USB handle — a stick — as the second search volume; flight 25's USBSLOT put a stick in the global slot).
- **Rule.** SECURITY.md §Process & supply chain (self vs non-self loader check); R95 (removable media are volumes,
  not system sources).
- **What it does.** With the card lacking the set, a stick carrying `ucode29_mimo.fw` supplies the d11 microcode the
  bring-up uploads to a bus-mastering PCIe device on a machine without an IOMMU policy.
- **Fix (arc).** Pin SHA-256 per role (`hash::sha256`, from the bench's measured set: ucode 39760 bytes, initvals
  477 records, bsinitvals 35 records) and refuse a mismatch; search only the boot card's ESP; refuse `violates-layout`.

## F6 — LOW — a `Vec<u8>` viewed as `[u32]` on an alignment the allocator does not promise (note)
- **Where.** `video/quarry/live.rs:1834` (older than this wave). The SAFETY comment claims the global allocator
  aligns a `Vec<u8>` to 4; Rust promises align 1 for that layout. Fix: allocate `Vec<u32>` (one-line type change at
  `live.rs:1984`). Not patched: outside this wave's files.

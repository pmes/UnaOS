## Findings

### F1 — HIGH — two Principia stores since SETTINGSFILES
- **Where**: `unaos/crates/kernel/src/prefs.rs:17-22,150-163,374` (the store is `<home>/settings/<domain>`; the old
  `preferences.toml` is MIGRATED AND DELETED); `handlers/principia/src/lib.rs:85` (`config_dir.join("preferences.toml")`),
  `handlers/principia/src/wire.rs:92`. `grep prefs_core::files handlers/principia` = nothing.
- **Rule**: R79 (one store; a preference is Principia's); MACPARITY §16 B1 names "prefs_core store split + Principia".
- **What it does**: the kernel writes the domain files and deletes the TOML Principia reads; Principia writes the TOML
  the kernel only ever imports once. prefs.rs's own header still says "what the kernel writes, Principia reads
  unchanged" — false since B407.
- **Fix (ARC PRINCIPIAFILES)**: `handlers/principia` PrefStore loads/saves through `prefs_core::files`
  (`split`/`render`/`domain_of`, `DIR`), the same migration (`preferences.toml` → `settings/<d>`), cross-test in
  `handlers/principia/src/prefs.rs` that a kernel-rendered folder round-trips; drop the stale header sentence.

### F2 — HIGH (security) — Bluetooth link keys stored in the clear beside Holocron
- **Where**: `drivers/ehci/bthid.rs:2429-2450` `store_write`: `<home>/.config/unaos/bt/<addr>` with
  `set_attr("bt.linkkey", Blob(16 bytes))`; header line 3 "carried as typed attributes until Holocron exists — owed".
- **Rule**: R79 / CODEX §2 (secrets are Holocron's); SECURITY.md:268-269 (classed-record store, encryption "named as the
  successor"). Holocron now EXISTS with sealed records (`keyring.rs`, `holocron_core::ring` HKDF file keys,
  `crates/user-holocron`) — the "until" has passed.
- **What it does**: a link key (a pairing secret: whoever reads it impersonates the keyboard) sits as a plain blob
  attribute readable by anything with read on the home; it is invisible to GATE-CHARTER (F10).
- **Fix (ARC BTKEYSEAL)**: store each bond as a Holocron secret (`bt/<addr12>` in the `bt` namespace) through the
  keyring fulfiller; one-shot migrate-and-unlink the attribute files; SECURITY.md row updated.

### F3 — HIGH (security) — a document attribute can name any program, and a copy carries it
- **Where**: `fs/assoc.rs:89-92` (a file's `una:preferred` wins, value unchecked), `video/quarry/openers.rs:138`
  (`prog if prog.starts_with('/')` → `open("launch", prog, …)`), `fs/filetype.rs:389-392` `carry_in` copies
  `una:type` and `una:preferred` with the bytes (shell.rs:701).
- **Rule**: SECURITY.md posture (no execution without the user's act on the PROGRAM); Be's PREFERRED_APP named an app
  SIGNATURE resolved through the registrar, never a path.
- **What it does**: a file arriving on a UnaFS card, an archive or a copy can carry `una:preferred=/home/u/Downloads/x.elf`;
  double-clicking the DOCUMENT launches that ELF with no dialog.
- **Fix (ARC OPENERTRUST)**: an override must name an opener id or a program APPRES has registered (`una:apps` /
  `una:signature`), resolved by signature; a path outside the registered programs is refused on the wire and shown
  as an alert (DIALOG); `carry_in` drops `una:preferred` when the source volume is not the boot volume.

### F4 — HIGH — two Holocron store roots
- **Where**: kernel `keyring.rs:61` and ring-3 `crates/user-holocron/src/main.rs:575` use
  `<home>/.config/unaos/holocron/`; the host handler (`handlers/holocron/src/store.rs:33`, `unafs_store.rs:42`) and the
  core's own format doc (`holocron_core/src/format.rs:8,32`) use `<home>/.holocron/`.
- **Rule**: R79 (one store); the core both rings link does not carry the path, so each ring invented one.
- **What it does**: a UnaFS volume prepared on the host (the card image, the installer) holds its ring at `.holocron/.ring`;
  UnaOS looks at `.config/unaos/holocron/.ring` and sees no ring — two stores for one user.
- **Fix (ARC HOLOCRONROOT)**: `holocron_core::format::STORE_DIR` (one const), both rings and the host use it; one
  migration; add the path to `charter.registry` (`.ring` is invisible to GATE-CHARTER today, F10).

### F5 — MED — two Trash implementations; the kernel's charter claimed a ruling it does not have
- **Where**: `fs/trash.rs` (575 lines: move/restore/empty, attribute store on UnaFS, `.Trash/.index` on FAT) and
  `handlers/matrix/src/trash.rs` (`VaultTrash`, the same `una:trash-*` keys from una-abi). The header read
  `Matrix — kernel-by-ruling R50`; R50 rules Quarry the always-running Finder and says nothing about the Trash;
  the registry row (and B288) say `owed`.
- **Fix**: PATCH 64fceedf restores `Matrix — owed B288` (comment only). ARC TRASHCORE: the move/restore/empty rules into a
  `no_std` core (beside una-abi's keys, generic over the MountTable/UnaFS seam) that `fs/trash.rs` and Matrix both link.

### F6 — MED — the type registry has a host twin
- **Where**: kernel `fs/filetype.rs:94` EXT_TABLE + `sniff_core` (magics inlined before the cores' `mime_of`),
  `elf_flavour` (`:163`, its own PT_LOAD walk beside `elf_core::read_phdrs`); host `libs/bandy/src/signals.rs:530`
  `image_mime_for` — "the host twin of the kernel type database".
- **Rule**: R79; MACPARITY §16 B3 (ONE FileTypes registry: icon, opener, sniff rule).
- **Fix (ARC TYPECORE)**: a `no_std` `type_core` (or a `midden_core::types` module) owning the extension table, the
  sniff order and the ELF split; filetype.rs and bandy call it; GATE-ARCH `parser` rows for filetype shrink.

### F7 — MED — the launcher writes into Principia's folder beside the store
- **Where**: `video/launcher.rs:722-785`: `<home>/settings/launcher` built with `PrefTree` and written by raw `mt.write`
  (no `.new` swap, no `# auto-saved` line, not through `prefs`/`prefs_client`, invisible to Settings' domain list).
- **Fix (ARC LAUNCHERPREFS)**: `app.launcher.recent` through `prefs::set` (APP_NS → `settings/launcher` by
  `files::domain_of`); delete lru_save's writer. GATE-ARCH `settings` row shrinks.

### F8 — MED — the player window declared `Kernel — wm`

  engine `drivers/hda_play.rs` is already `Stria — owed B289` in the registry.
- **Fix**: PATCH 767a92bf → `Stria — owed B289`. The Stria seam stays owed with B289.

### F9 — MED — the attribute namespace has six homes
- **Where**: keys as constants in `fs/filetype.rs:30`, `fs/assoc.rs:22-25`, `fs/attrfacts.rs:32-43`, `fs/appres.rs:52-55`,
  `una-abi` (trash keys), `midden_core` (res keys), plus raw literals in `video/player.rs:185,189`, `drivers/ehci/bthid.rs`

- **Fix**: PATCH 0b860960 (player reads `attrfacts::DURATION`/`CODEC`). ARC ATTRKEYS: one key table in una-abi (the
  trash block is the shape), every kernel module and ring-3 handler imports it; a key literal outside it is refused.

# BP-ring3 — programs on UnaOS: ABI, bus, ELF, slots, windows, float (read at 1719fe54)

## 1. What it is
- A ring-3 program is a static ELF from a `user-*` crate in `unaos/crates/`, staged as `/apps/<NAME>.ELF` on the root volume and launched by its bare name (R82, R94).
- The ABI crosses through `una-abi` (70 `SYS_*` numbers 1..76; packed input words; bus verb numbers) (`unaos/crates/una-abi/src/lib.rs`). Each arch's `syscall.rs` owns only the user copy and the trap.
- The bus (`unaos/crates/kernel/src/bus.rs`) is the on-UnaOS SMessage v1 codec: a fixed 52-byte header plus typed payloads over `SYS_MSEND`/`SYS_MRECV` (19/20).
- A handler that lives on UnaOS either IS a ring-3 program (Holocron, Stria, Aether, …) or is FULFILLED by the kernel through its bus verbs (Principia's prefs).
- UnaOS ring-3 code on x86 has the x87/SSE unit (hardware float, SSE/SSE2, no AVX) with a per-task FXSAVE context (B666). aarch64 ring-3 targets carry `+neon`.

## 5. Ruled, unbuilt / open
- FPU/SSE context for UnaOS ring 3: built (B666, BP-ring3-11), unflown. TEMPLE measured fixed point 5594 ms vs the 3000 ms bar, f32 2127 ms (host, commit `d92a36b7`); the on-UnaOS f32 number is owed to a flight.
- EL0 name verbs (§7, PATHNS SR171): `SYS_ATTR_SET/GET/LIST`, `SYS_STAT`, `SYS_PATH_READ/WRITE` (aarch64 only under `selfdiag`) and `SYS_SPAWN_PATH` take an absolute path through the VFS mount table; `SYS_OPEN` takes a path on aarch64 (the EL0 FAT volume, DIRNS) and on x86 a root leaf without `irqstorage`, a path through `sys_open_dynamic` under `irqstorage` (image-line.env does not arm it); `SYS_RENAME` takes a root leaf on both arches; `SYS_UNLINK`/`SYS_FGRANT` take a handle.
- Window verbs on aarch64: `BUS_VERB_SCROLL_SET` (28, SCROLLARM64 SR172), `BUS_VERB_WINDOW_RAISE` (26) and `BUS_VERB_A11Y_TREE` (25) (RAISEARM64 SR175) are answered on both arches; `wm::focussteal` and `wm::a11y` compile on both desktops (`focussteal::note_arm` stays x86: its door `arch::memory::current_slot` is x86-only).
- Map-time FOCUSSTEAL on aarch64 (RAISEARM64 SR175, owed): `spawn_focus_arm`/`spawn_focus_take`/`spawn_focus_forget` and `create_inner`'s `hold_under` fold are x86 `wc` and aarch64 never calls `spawn_focus_arm`, so nothing on aarch64 arms the verb-launch record (its `oneinstance_gate` grants by itself) and an aarch64 raise is given only when the asker holds focus (`cause=focused`), else pulsed; the refusals are x86's. Needs aarch64's `current_slot` (private in `arch/aarch64/xwin.rs`) reachable by wm. Owed.
- `docs/dev/blueprint/input.md` §5 still says ring-3 windows have no scroll registration verb (stale since RING3SCROLL B778); owed to that sheet's next arc.
- The skip-and-drop reply loops outside `bus_ask` (MAILBOXKEEP SR177's owed row: vein_ring3 drop/prefs/holocron, the four theme `call`s): closed by DROPLOOPS (LEDGER SR179), BP-ring3-19.

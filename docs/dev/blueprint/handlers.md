# BP-handlers — the CODEX manifest and the host userspace (read at 1719fe54)

## 1. What it is
- `docs/CODEX.md` §2 is the handler manifest: LOCKED, 21 handlers (Amendments I Helm, II Aether as a JS browser). Each owns one domain.
- Each handler is a host crate under `handlers/` (root workspace). `handlers/sonde/` is a 22nd directory; its CODEX row (Amendment IV, R112) awaits Peter's signature.
- On UnaOS a handler appears as (a) a ring-3 ELF, (b) a kernel fulfiller of its bus verbs, or (c) a kernel app file whose `CHARTER:` names it (seam `shared-core` / `owed B<n>`), listed in `unaos/scripts/charter.registry` (93 lines).
- Host libraries: `libs/gneiss_pal` (platform layer), `libs/bandy` (bus), `libs/quartzite` (GUI), `libs/elessar` (workspace binder), `libs/euclase` (wgpu), `libs/lux`, `libs/resonance`, `libs/text_host`.
- Vessels compose handlers into apps: `vessels/lumen`, `vessels/una`, `vessels/pulse`, `vessels/phonolite`, `vessels/facet-view`, `vessels/aether-shell`. aether-shell's faces (AETHERMAC SR196, AETHERMACCHROME SR205): GTK grows Quartzite's browser chrome (`platforms/gtk/mod.rs` `bootstrap_browser_chrome`); macOS (AppKit, chosen by `target_os` alone, the `macos` feature naming only the run line `--features macos -- <url>`) grows its own, `platforms/macos/mod.rs` `bootstrap_browser_chrome`: the tetra toolbar (`eval_tetra`, `tetra_eval.rs`) over the side tab column (`tab_strip.rs`), the find bar (`find_bar.rs`, Cmd+F), the page surface and the downloads (`downloads.rs`), the status line (`status_line.rs`) at the foot; both faces paint the ONE wire the shell's `Coordinator` publishes from its `TabStrip` (`chrome::tabs_message`) and fire the same verbs back (`Coordinator::on_bus`); the face's rows and text are written once, platform-neutral, in `libs/quartzite/src/widgets/chrome_rows.rs` (`side_rows` = `TabStrip::rows` over the wire), and the GTK face reads it too (ONETEXT SR210: `platforms/gtk/tab_strip.rs` `fill_side`, `platforms/gtk/image_view.rs` `bootstrap_page_view`; no face keeps a copy); the headless fallback keeps the tetra toolbar; every face opens its first argument through the omnibox's own `OpenDocument` (`start_url`, `vessels/aether-shell/src/main.rs`; the GTK `Backend::run` hands GApplication no argv, `run_with_args`).

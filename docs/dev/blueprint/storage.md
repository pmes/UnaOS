# BP-storage — block, FAT, UnaFS, VFS, root, prefs, users, install (read at 1719fe54)

## 1. What it is
- Block layer: `unaos/crates/kernel/src/drivers/block.rs` with handles `Global`, `Usb`, `Sdhc` (x86 `sdhcblk`), `TegraSd` (`tegra`+`sdmmc`) (`unaos/crates/kernel/src/drivers/block.rs:563-585`); AHCI (`unaos/crates/kernel/src/drivers/ahci.rs`), USB mass storage on xHCI, Pi `unaos/crates/kernel/src/drivers/emmc2.rs`.
- Filesystems: FAT (`unaos/crates/kernel/src/fs/fat.rs`), exFAT (`exfat_core`), UnaFS (`unaos/libs/fs/unafs`, on-disk v7; kernel glue `unaos/crates/kernel/src/fs/unafs.rs`).
- ONE namespace: the VFS `MountTable` (`unaos/crates/kernel/src/fs/vfs.rs`) is the only place a name is decided; `/volumes/UnaOS` IS `/` (`unaos/crates/kernel/src/fs/rootdisk.rs:7-13`).
- The root is the disk the kernel was found on, by content (`unaos/crates/kernel/src/fs/bootdisk.rs:592-612`); on the rMBP image it is UnaFS on the card, or the internal SSD's UnaFS partition when it is OURS (`unaos/crates/kernel/src/install/ahciroot.rs:6-20`).
- Stores on the root: Principia's preferences (`<home>/settings/<domain>`), the users table (`/system/USERS.DAT` on an x86 native UnaFS root, `/USERS.DAT` on a FAT-root boot; `unaos/crates/kernel/src/fs/users.rs:3593-3648`), homes `/home/<name>`, `/apps`, `/lib`, `/var`.

## 5. Ruled, unbuilt / open
- R94's hot swap of the root volume: design only (`unaos/crates/kernel/src/fs/rootdisk.rs:24`).
- Pi storage (emmc2/SD root on bare metal) at HEAD: `unverified` (not read for this sheet).
- PIHOME (LEDGER SR176): BUILT by PIUNAFS (LEDGER SR178) as fix (a), `export UNAOS_UNAFS=1` on both aarch64 lines (§2.1); the three comments read true. OWED by it: `el0_session_base` (`unaos/crates/kernel/src/fs/vfs.rs:3260`) returns a FAT cluster of the EL0 volume, so on a native-root aarch64 image a relative EL0 path starts at the FAT volume root (or a stale `HOME/<NAME>` an earlier image left), not the UnaFS home; the base becomes the native home only when the EL0 path verbs resolve through the mount table (`docs/dev/blueprint/ring3.md` §7, PATHNS SR171).
- FILEVERSIONS' §R17 record is ADDITIVE under the unchanged v7 stamp, so a pre-B714 `fsck --repair` rebuilds refcounts without the rings' references and can free blocks a version still names (crawl B finding 5). Stopgap built (the restore guard, BP-storage-24); the fix is a format change and a STOP for the crawl (VERSIONSCOMPAT, LEDGER SR154, owns it): (a) a ROCOMPAT bit (`RootRecord::flags` bit 2, set by the first version capture) with the rule, from that build on, that a reader refuses `--repair` and writes over a root flag it does not know — closes the gap for every LATER reader but not the pre-B714 ones, which read `flags` (`unaos/libs/fs/unafs/src/root.rs:109`) and ignore unknown bits; (b) for the readers that already exist the only refusal is the stamp: a versioned volume stamped past 7 (INCOMPAT), which costs pre-B714 builds the mount entirely.
- EL0 name verbs: ring3.md §7 (PATHNS SR171): the attribute, stat, path-I/O and spawn verbs take an absolute VFS path; `SYS_OPEN` a path on aarch64 (EL0 FAT) and a root leaf on x86 unless `irqstorage`; `SYS_RENAME` a root leaf; `layout.md` §5.2 says the same.

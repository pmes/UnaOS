# JSCORE — js_core, ECMAScript 2025 from the specification (LEDGER SR55)

Branch `exec-web-jscore`, crate `unaos/libs/web/js_core` (root workspace member). `no_std` + `alloc`,
`#![forbid(unsafe_code)]`, **zero dependencies** (one dev-dependency, the in-tree `crypto_core`, used by
nothing but tests). Aether is untouched; the boa → js_core swap is the follow-on (EYES-gated).

**SR55 status: JSCORE milestones M1–M5 done on `exec-web-jscore` — test262 run mode 42220/42351 = 99.69 %
(built-ins 99.56 %, language 99.78 %, language/expressions 99.82 %, language/statements 99.75 %, annexB 100 %;
parse mode 42351/42351); Chromium oracle 3/3 pages byte-identical; fuzz 10000 mutants (two seeds, 20000 total):
0 crashes, 0 timeouts, peak child RSS 16.5 MiB under a 512 MiB cap; bench vs boa 0.22 geometric-mean time
ratio 0.56 (js_core faster on 6 of 8 kernels); `cargo test --release -p js_core` green. The Aether swap
(boa → js_core) is the follow-on.**

## Shape

The same shape as HTMLCORE / CSSCORE: a standalone core with a narrow host interface, proven against the
official conformance suite, a browser oracle, a fuzzer and a baseline benchmark.

```
source (UTF-16) ─ lexer ─ parser ─ AST (ESTree-shaped, scope ids, early errors)
                                     │
                         compiler: scope analysis (pass 1) → stack bytecode (pass 2)
                                     │
                         VM: frames on one value stack, handlers, coroutines, job queue,
                             heap arena + exact mark-sweep GC, realms, modules
                                     │
                         built-ins (§19–§28) ── host hooks (console, timers, module loader,
                                                 promise rejection, clock, time zone)
```

| Layer | Files | Notes |
|---|---|---|
| Lexer | `src/lexer.rs` | UTF-16 source, parser-driven: re-scans `/` as a RegExp and `}` as a template continuation; ASI flags; escaped-keyword tracking. |
| Parser | `src/parser/{mod,expr,stmt}.rs`, `src/ast.rs` | Recursive descent, cover grammars (`CoverParams` / `CoverPat`) for arrows, destructuring and `async (…)`; every early error of the spec incl. redeclarations, private names per class, `arguments` in fields, regex literal validation. Nesting bounded (`MAX_NESTING`) so input cannot exhaust the native stack. |
| Compiler | `src/compiler/{mod,scope,expr,pattern}.rs` | Pass 1 marks captured / eval-visible / dynamic (`with`, sloppy direct eval) bindings and Annex B.3.3 hoisting; pass 2 allocates registers vs environment slots and emits stack bytecode. Statements leave the stack empty; a control stack routes `break` / `continue` / `return` through `finally`, iterator close and environment pops. |
| Bytecode | `src/bytecode.rs` | ~170 ops; `Code` carries constants, scope infos, declaration lists, source text for `Function.prototype.toString`, module records. |
| VM | `src/vm/*` | `Value` (UTF-16 `JsStr`, `Rc` symbols / BigInts, `u32` object handles, an internal hole/TDZ marker); JS→JS calls run in-loop, native→JS calls in a nested loop; generators / async functions / async generators / module bodies are coroutines (the frame and its stack segment move into a heap object at a suspension). |
| GC | `src/vm/heap.rs` | Exact tracing mark-sweep over a handle arena; ephemeron WeakMaps, WeakRef, FinalizationRegistry cleanup jobs. Roots: value stack, frames, handlers, realms, queued jobs, timers, modules, and `temp_roots` — natives keep what they allocate *and what they are handed back* rooted until they return. Collection only at interpreter safepoints. `gc_stress` collects at every safepoint. |
| Numbers | `src/numconv.rs`, `src/bignum.rs` | Exact dtoa (shortest round-trip) / strtod / toFixed / toPrecision / radix conversion on a `BigUint`; `Math` on a double-double core (no libm in `no_std`), correctly rounded `sqrt`. |
| Unicode | `src/unicode/*` (generated by `tools/gen_unicode.py`) | UCD 17.0.0 only: identifiers, white space, general category, scripts + extensions, binary and string (emoji) properties, case mapping and folding, NFC/NFD/NFKC/NFKD. URLs + sha256 in `tools/ucd.txt`. |
| RegExp | `src/regexp/{parser,matcher}.rs` | §22.2 grammar incl. Annex B, named groups (duplicates in alternatives), lookbehind, modifiers `(?ims-ims:)`, `v`-mode set operations and strings. The tree compiles to a small instruction program run by a backtracking loop with an explicit backtrack stack (no native recursion per character); case-insensitive matching uses Canonicalize (simple case folding in Unicode mode, toUppercase otherwise) with an inverse table; a step budget turns catastrophic backtracking into a RangeError. |
| Time zones | `src/tz.rs` | Time zones as data: a POSIX TZ rule string (the footer rule of IANA TZif data, e.g. `CET-1CEST,M3.5.0,M10.5.0/3`) drives LocalTZA, with the spec's choice for skipped/repeated local times. No OS database; an embedding without a rule may answer LocalTZA itself (`Host::tz_offset_ms`). Historical transitions (the TZif table body) are not modelled — the current rule applies to all years. |
| Host | `src/builtins/host.rs`, `Host` trait in `src/vm/mod.rs` | `console.*`, `setTimeout`/`setInterval`/`clear*`, `queueMicrotask`; a virtual-time event loop (`Vm::run_event_loop`) for hosts without their own; microtask checkpoints that report rather than propagate exceptions; `load_module` (HostLoadImportedModule), `promise_rejection`, `now_ms`. Resource limits for untrusted code: instruction budget (also charged by property access inside built-ins), heap-cell cap, string-length cap. |

Built-ins: everything in ECMA-262 2025 except Intl (deferred: `toLocale*String` are the plain forms) and
the out-of-scope proposals listed below. Also implemented beyond ES2025 where test262 has tests and the
proposal is at stage 3+/4: Float16Array + `Math.f16round`, `RegExp.escape`, `Promise.try`, Iterator helpers
incl. `chunks` / `windows` / `includes` / `join`, Set methods, resizable / transferable ArrayBuffer,
`Error.prototype.stack` accessor, `Atomics` (single agent).

### Chromium oracle

`tests/oracle/page{1,2,3}.html` (language/number formatting/RegExp/Date/typed arrays; DOM building;
task/microtask ordering with timers, async functions, async generators and Promise combinators) run on
js_core through a tiny test DOM (`tests/oracle/dom.js` + `host.rs`: HTML parse, DOM build, inline scripts in
order with a microtask checkpoint after each, event loop, HTML serialization) and in
`chromium_headless_shell-1194 --dump-dom --virtual-time-budget=10000`. **All three pages: serialized DOM byte-identical** (7.1 KB, 2.7 KB, 2.7 KB). The Chromium dumps are
recorded as `tests/oracle/page*.chromium.html` and the `oracle` test compares against them, so the gate needs
no browser; `js_core-oracle` re-runs Chromium when present (`--record` refreshes the references). Two
findings while building the pages: Chromium (this build, in this container) dies with SIGILL on a page that
writes lone surrogates into the DOM, and a page without `<meta charset>` is decoded as windows-1252 — the
pages declare UTF-8 and avoid lone surrogates in DOM text. EYES 12-js-mutation is an Aether page; it is part
of the swap arc, not of this standalone core.

### Fuzz

`js_core-fuzz -n 10000 --corpus <test262>`: deterministic xorshift mutations (numeric-literal replacement,
snippet insertion, span delete / duplicate / swap, line splicing across seeds, hostile prelude statements,
punctuator flips) of 1188 seeds (the oracle scripts, built-in snippets and every 40th test262 file with a stub
harness). Each mutant runs in a child process under `ulimit -v` (512 MiB), a 5 M-instruction budget, a
300 000-cell heap cap, a 4 Mi-unit string cap and a 10 s watchdog; every eighth mutant runs with
`gc_stress`. Results: seed `0x5eed1234abcd0001` — completed 2676, threw 7320, budget-terminated 4, timeouts 0,
**crashes 0**, peak child RSS 16 500 KiB; seed `777` — completed 2601, threw 7399, timeouts 0, **crashes 0**,
peak 15 916 KiB. (The first 10000-run, before the fixes below, found two native loops over 2^53-length
array-likes that ignored the budget; property access inside built-ins now charges the budget. `gc_stress`
found five exact-GC rooting holes, all fixed: values handed back to natives by calls/constructs, the job
being run, operands popped off the stack across user-code conversions, class static elements, the
promise-resolution `then` lookup.)

### Benchmark vs boa 0.22

`bench/*.js` — Octane-style kernels written for this crate (richards scheduler, splay tree, Navier-Stokes
solver, ray tracer, RSA-style bignum modexp, RegExp log processing, JSON round trips, closures/generators/
collections). `js_core-bench --other <boa runner>`: each kernel as a fresh process on both engines, best of
3, minus each engine's empty-script startup. The boa runner is `boa_engine 0.22.0` (crates.io, latest
stable) behind a 20-line `main` with a `print` global, built in the scratchpad (not a dependency of this
repo). Ratio = js_core time / boa time (lower is better for js_core).

| kernel | js_core s | boa 0.22 s | ratio | output check |
|---|---:|---:|---:|---|
| closures | 0.307 | 0.352 | 0.87 | same |
| crypto | 0.297 | 0.269 | 1.10 | same |
| json | 0.237 | 0.890 | 0.27 | same |
| navier | 2.685 | 2.137 | 1.26 | same |
| raytrace | 0.343 | 0.505 | 0.68 | same |
| regexp | 0.795 | 11.133 | 0.07 | same |
| richards | 0.207 | 0.281 | 0.74 | same |
| splay | 1.213 | 1.392 | 0.87 | same |

Geometric mean 0.56. Honest reading: both are interpreters; js_core wins big on RegExp (compiled matcher vs
boa's) and JSON, modestly on object-heavy code, and loses on tight numeric loops with many small calls
(navier, crypto) — the next speedups are inline caches for property access and call-site arity fast paths.

## Ceiling (what is not done)

- **Intl** (ECMA-402) is not implemented (`toLocale*` are the plain forms) — deferred per the arc.
- **Agents**: `$262.agent` is a stub, so the multi-agent Atomics tests (59 of built-ins/Atomics) fail;
  SharedArrayBuffer memory is not shared across threads. `Atomics.wait` throws (main agent [[CanBlock]] false).
- **Time zones**: one POSIX rule per zone (the TZif footer), no historical transition table.
- **Function `caller` / `arguments` legacy properties** (feature `caller`, 19 + 2 tests) are not provided.
- Remaining language failures (50): `(fn) = function(){}` naming through parentheses, keyed destructuring
  evaluation order with computed keys, iterator close on `return` inside array destructuring assignment
  (6 tests), async-generator return-await tick order, `undeclared = …` resolved before the RHS in strict
  code, two module-namespace ambiguity cases, TLA rejection order, `eval` in class field `arguments` errors.
- Performance: no inline caches, no shape-based property lookup, no JIT; navier/crypto are slower than boa.
- Resource limits are cooperative: the budget is charged by bytecode and by property access in built-ins;
  native stack depth is bounded by parser nesting (`MAX_NESTING` 1500) and call depth (1800) — an embedder
  running scripts on threads should give them ≥ 8 MiB of stack.
- The tiny oracle DOM handles the oracle pages' well-formed HTML only; the real DOM binding is Aether's.

## How to continue

```
cargo build --release -p js_core --examples          # from the worktree root
./target/release/examples/js_core-test262 <test262> [-v] [-j N] [filters, !exclude]   # JS_GC_STRESS=1 for stress
./target/release/examples/js_core-run [--gc-stress] file.js | -e 'src'
./target/release/examples/js_core-oracle [--record]   # needs chromium_headless_shell for re-recording
./target/release/examples/js_core-fuzz -n 10000 --corpus <test262> [--seed S] [--save dir]
./target/release/examples/js_core-bench --other <boa-runner>
JS_TEST262_DIR=<test262> cargo test --release -p js_core   # the gate (test262 parse + run, oracle, KATs)
```
Next arcs: (1) the Aether swap — implement `Host` in Aether (timers into its event loop, module loader,
console) and bind the DOM, gated by EYES 12-js-mutation; (2) inline caches + shapes for the bench gap;
(3) the remaining 50 language tests listed above; (4) agents (threads with `Arc`-backed shared buffers) for
Atomics; (5) Intl.

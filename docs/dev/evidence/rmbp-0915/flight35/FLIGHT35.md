## 4. Findings
- **GATESTEAL (the SESSIONWEDGE family's mechanism, named twice this flight):** the compositor's serialised gate (`wcser`) is held by core 7 — the usb-pump's core — through a long pump step (boot 1: `bootlog`; boot 3: `prtscr`, the 15 MB PNG write), the W5 watchdog NMIs core 7 after 1.5–1.7 s and STEALS the gate (`dead=c7`), and the pump task on that core NEVER RUNS AGAIN: `pump=9@cpu7 stopped, holds=[] waits=none`. USB input and the serial door ride the pump, so the glass dies while the wire stays alive through the cable rescue. Flights 29/33's silent wedges cut mid-print are the same shape (the NMI landed on the printing core). The pump's long steps (bootlog, prtscr, the trackpad holes' `step=bootlog`) must not hold the compositor gate, and W5's steal must hand the core back, not leave it dead.

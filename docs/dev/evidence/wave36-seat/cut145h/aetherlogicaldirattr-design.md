## Design: the store is font_rel itself (no new field), ONE resolver in the prepass
1. STORE (css.rs `apply_logical`, in place, TWO one-line folds): an INLINE-axis side logical, horizontal-tb, with no direction declared on the element yet (`style.paint.rtl.is_none()`), still writes the ltr physical side exactly as today (ltr result unchanged), but font_rel records the LOGICAL declaration `(prop, value)` instead of the physical name(s) it wrote: on `let (start, end) = ...` (:1908) append `let kept = logical_dir_keep(inline, mode, style);` (takes font_rel aside); on the `return true;` after the side match (:1948) prepend `logical_dir_store(kept, prop, value, style);` (puts font_rel back and pushes the logical entry iff an arm accepted, i.e. the nested physical write recorded something). So font_rel holds logical and physical declarations interleaved in true cascade order (in-block and across rules / tiers through merge_paint) = css-logical-1 §4 order is reachable: AETHER-LOGICAL-CASCADE-ORDER BUILT, not owed. Declared-direction elements (`direction: rtl; padding-inline-start`) keep today's road (physical recorded).
2. RESOLVE (tree.rs, ONE call folded onto :1189 before `rtl_start_blocks`: `logical_dir_resolve(tree, id);`, body = tree.rs tail fn `logical_dir_resolve` — in tree.rs, not css.rs, because `refold` is tree.rs-private; the alternative is making `refold` pub(crate), a second tree.rs line; the seat picks): for a box whose font_rel holds an inline logical name AND `is_rtl(tree, id)`: build ONE replay SpecifiedStyle (seeded with the box's border / border_style / border_width / inset_px arrays, and `paint.rtl = Some(true)` so apply_logical maps rtl), (a) reset each physical side the parse wrote (found by applying the logical entry to a probe spec with rtl=Some(false) and reading the probe's font_rel names) through the property's own `initial` road (`noninherited_initial`: margin/padding 0px, inset auto, border side none; `-width` -> `medium`), (b) replay every font_rel entry of the touched families (margin*, padding*, border*, inset*/top/right/bottom/left) in cascade order through `css::apply_declaration` (the SAME arm the physical property uses; no second box-side writer), (c) `paint.rtl = None` (no declared direction invented), `refold(tree, id, spec)`, and (d) the box's font_rel becomes its non-family entries + the replay spec's own font_rel (physical rtl names), so the later font-relative / container-unit replays keep the right side and a second prepass is a no-op (idempotent). ltr boxes: early return, nothing written.
- ltr: the taffy styles and paint are byte-identical (same physical writes); font_rel content differs (logical name, the displaced earlier physical entry kept), which only the two replays read and they reach the same values (apply_logical maps ltr in a replay). Edge stated: an element whose only font-relative length was a physical side displaced by a later logical now triggers reresolve_font_relative (same final values).

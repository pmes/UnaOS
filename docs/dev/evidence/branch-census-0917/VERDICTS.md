## Method — what earned each verdict

1. **Patch-id equality (c).** `git log -p` of every track commit since 2026-07-01 through
   `git patch-id --stable` (3,816 ids), against the same for each branch's commits not in any track
   (391 commits). **85 branches have a TIP whose patch-id is already on `main`** — cherry-picked,
   verbatim. This is the verdict the seat's line probe could not see: `exec-pidesk` probed 3/12 and
   `exec-r7-wmpaygo` 3/12, and both are byte-identical folds. Of the 26 rows in
   `UNREACHED-LOW-PROBE.txt`, **14 are patch-id folds** — the probe was measuring context drift, not
   loss.
2. **Fold-name + confirmed hunk (a).** For the remaining 88, `git log -i -F --grep=<NAME>` on the four
   tracks, then the fold commit's diff read against the branch's key hunk.
3. **Distinctive line in the track tree (b).** Each unfolded commit's added lines ≥45 chars,
   `git grep -F` against each track at HEAD, same file first then tree-wide. Per-branch hit/miss in
   `../../../../branchcensus-logs/` is scratch; every cited line is re-derivable from this repo.
4. **Adjudication records.** Two already existed and settle 19 rows between them:
   `docs/dev/evidence/orin22/DISPOSITION.md` (per-commit A/B/C disposition of the orin 20-22
   render10 stack, on `main`) and the branch tables in `hw-jetson:docs/dev/OS/orin-queue.md` /
   `hw-rmbp:docs/dev/OS/rmbp-queue.md`.

**(4) Would the seat's proposed rule have caught every LOST row?** It would have made 21 of 23
**visible**, and would have prevented none. Two gaps, and they are the two that actually happened:

- **Where the close-out is written is not part of the rule.** The 2026-09-13 session obeyed the rule's
  substance perfectly — every one of the fourteen branches is listed with its tip sha and its state —
  and all fourteen are still lost, because the list lives on `hw-jetson` and the shared code in them
  belongs to trunk. FONTS2X was found by Peter looking at blocky glass, not by anything in git.
- **One branch name is not one tip.** MATRIXPAR is `ce0d992b` on origin and `5c1f13d0` locally, with
  different content. A rule keyed on the branch *name* records one fold sha and silently drops the
  other ref.

**What would catch them is a gate, not a discipline.** The census that produced this table is four
`git merge-base --is-ancestor` calls per ref and runs in seconds. Teach `unaos/scripts/ledger-check.sh`
(or a sibling `branch-check.sh`) to enumerate every `refs/heads/exec-*` and `refs/remotes/origin/exec-*`,
**per ref, not per name**, and RED when a tip is an ancestor of no track branch and is older than a
stated window — with an explicit registered-exception line, the same shape GATE-LEDGER already uses
for its one field-count exception. A rule a seat must remember fails exactly when the seat runs out
of credit, which is precisely when these fourteen were lost. A gate does not.

# exec-branches.txt — THE EXECUTOR BRANCH REGISTRY. Read by GATE-BRANCH (unaos/scripts/branch-census.sh,
# called by unaos/scripts/ledger-check.sh, which `arroyo check` runs).
#
# An executor branch is CLOSED by a line here naming its fold sha — not by a seat remembering. Every
# `refs/heads/exec-*` and `refs/remotes/origin/exec-*` whose tip is an ancestor of NO track branch
# (main · hw-rmbp · hw-jetson · hw-pi4, local and origin) must have a line here or the gate REDs. A
# ref whose tip IS on a track needs no line: git has already closed it.
#
# ONE LINE PER REF, FIVE FIELDS:
#
#     <ref> <tip-sha> <state> <fold-sha-or-owner> <date>
#
#   <ref>       the FULL refname. PER REF, NEVER PER NAME — `exec-orin22-matrixpar` is `ce0d992b` on
#               origin and `5c1f13d0` locally, two versions of one arroyo change, and a record keyed
#               on the name silently drops one of them (VERDICTS.md §Findings 4).
#   <tip-sha>   the sha this line judged. A CLOSED line must still match the ref's tip; an IN-FLIGHT
#               line records where the executor was CUT and its branch may only move FORWARD from it.
#   <state>     IN-FLIGHT · FOLDED-BY-HAND · SUPERSEDED · WIP-SURVIVOR · LOST. May be written with
#               its argument appended (`FOLDED-BY-HAND:<sha>`); then field 4 is `-` or the same one.
#   <field 4>   FOLDED-BY-HAND/SUPERSEDED: the fold sha — it must resolve here AND be an ancestor of
#               a track, because a fold nobody can fetch is not a fold. LOST: the queue file that
#               owes the rescue. IN-FLIGHT: the seat that cut it. WIP-SURVIVOR: `-`.
#   <date>      the branch's date; for IN-FLIGHT, the day it was cut (more than 14 days old REDs).
#
